# Presentation design

Read for any slide deck, including HTML decks. Apply the selected theme;
format-specific tools own rendering, export, and editing.

**Structure.** One idea per slide, a clear headline, short phrases, generous
whitespace, and a visible hierarchy. Use no more than four bullets per slide;
split dense explanations. Start with a hook, develop the mental model, and
end with a recap or next action. Keep factual citations compact and readable.

**Layouts.** Choose what serves the content: title, agenda, section break,
single statement or statistic, two- to four-panel comparison, diagram,
photo with explanation, quote, table, or timeline. A layout is a tool, not a
required slide. Avoid invented people, customer names, quotations, or data.

**Diagrams.** Use the smallest diagram that explains the relationship.
Render it into the delivery format rather than leaving raw markup. Use
[Mermaid conventions](../conventions-mermaid/SKILL.md) when applicable.
Keep standalone source or images only when requested or needed to reproduce
the deck.

**Size and legibility.** Default to 16:9 unless the brief or template dictates
another ratio. Use 24pt or larger headings and aim for at least 18pt body
text, checking the final rendered size. Split content before shrinking it.
Translate with room for longer text. Inspect clipping, overlaps, table and
diagram labels, and font substitutions in the actual delivery format.

**HTML decks.** Also load [HTML guidance](DESIGN-HTML.md). Theme switching
must update every slide and diagram while preserving the current slide.
Do not add interactive appearance controls to static PDF or PPTX exports.
