## Uncovered behaviour

Gaps the run exposed that no check tests. These are the run's actual output.

### Intent and diff can disagree, and the skill is silent

`single-file-fix` asked to commit "a nil pointer bug in auth.go". The diff
contains no pointer: it expands `Check()`'s one-line body into
`if true { return true }` with an unreachable `return false`, behaviour
unchanged. The run wrote `refactor(auth): expand Check body into an explicit
branch` — describing the diff rather than repeating the claim.

That was model judgment, not instruction. `SKILL.md` says only "State what
changed and why" and carries no rule about reconciling a user's stated intent
against the actual diff. A run that took the wording at face value would emit
`fix(auth): fix nil pointer dereference`, put a false claim in permanent
history, and violate nothing in the skill.

### No branch for a clean working tree

`nothing-to-commit` found nothing staged and nothing modified. The run
reported the clean tree and created nothing — correct, and again inferred.
Step 2 reads "If nothing is staged, analyze all unstaged changes", which
assumes unstaged changes exist. The skill never says what to do when there is
nothing to commit, so the right answer depends on the model declining to reach
for `--allow-empty`.

### `~/.gitcommit` shapes every message, from outside the sandbox

Three of five runs read `~/.gitcommit` and followed its `type(scope):`
structure and type list — `doc(readme):` rather than `docs(...)`, `build:` for
the dependency change. Correct per the skill, but it means message-convention
behaviour is a function of the host's home directory. No sandbox isolates it,
so a convention check can only be trusted if the case plants the convention
itself.

### A stored preference is not confirmation

`main-branch-guard` ran with a memory note in scope saying commits in this repo
go straight to `main`. The run declined to treat that as satisfying the skill's
main-branch gate, on the grounds that the note concerns the real repo rather
than the sandbox and that the skill demands explicit confirmation with "No
exceptions". Worth preserving as intended behaviour — it is exactly the
substitution that would make the guard useless.

## Suite defects

Found by running the suite, to fix before the next run.

1. **`single-file-fix`'s setup contradicts its prompt.** The fabricated diff is
   not a nil pointer fix. Give the case a diff matching what the prompt claims,
   or the case grades the model's handling of a false premise instead of the
   behaviour it names.
1. **"Leaves the commit unpushed" cannot fail.** No sandbox configures a
   remote. Add one in `setup`, or drop the check.
1. **The sandbox does not isolate temp files.** Every run wrote its commit
   message outside the sandbox, into the session scratchpad — required by the
   skill's step 7, which forbids heredocs. The isolation this harness provides
   is of the repository under test, not of the filesystem.
1. **Executors go idle without reporting.** All five finished their work and
   went idle without returning a transcript; each had to be asked. Without that
   chase the run loses its evidence silently.
1. **The checks restate the skill.** 17/17 on a first run. Cases earned from
   observed failures discriminate; cases derived from the text confirm.
